## 想解決什麼問題

身為工程師，每天都會被客服問到一樣的問題：「這個錯誤是客人自己關掉的嗎？」「那個設定在哪裡開？」

答案其實都回答過好幾次了，但散落在 Slack 的歷史訊息裡。客服找不到，只好再問一次；我每次都要停下手邊的工作，重新解釋一遍。

我想要的是：

- **客服的問題，先交給 AI 回答**，我只處理真的沒遇過的問題
- **新問題回答過一次，就不用再回答第二次**
- 不要增加客服的負擔，他們**照常在 Slack 問就好**

## 怎麼解決

核心想法很簡單：把回答過的問題整理成知識庫，讓 AI 照著知識庫回答。重點是最後一步：**答不出來的問題，工程師回答後要自動存回知識庫**，這樣知識庫會在日常使用中自己長大，不需要一次寫完。

    B -->|有把握| C[客服按「解決了」]

幾個設計上的原則：

- **只能根據知識庫回答**：寧可說「不知道，幫你找工程師」，也不要自己編答案
- **回答是給客服看的**：先給客服一句結論，再附一段可以直接複製給客人的回覆
- **個資自動遮掉**：客服一定會順手貼客人的 Email，靠提醒沒用，送給 AI 之前由程式先遮
- **大家一起維護**：每個工程師負責自己領域的 QA，用熟悉的 PR 流程審核

## 選什麼架構

| 角色 | 選擇 | 為什麼 |
|---|---|---|
| 提問入口 | **Slack** | 公司本來就用，客服不用換工具 |
| 知識庫 | **Obsidian 筆記放在 Git** | 就是 Markdown，AI 好讀；新增 QA 就是發 PR，可以多人審核 |
| 回答 | **Claude API** | 中文理解好，能照固定格式輸出，也會判斷自己有沒有把握 |
| 執行環境 | **Cloudflare Workers + Queues** | 不用顧主機；merge PR 就自動部署 |
| 部署 | **GitHub Actions** | 所有 key 集中放在 GitHub Secrets |

有兩個選擇值得多說一點：

**沒有用向量資料庫。** 一提到「AI + 知識庫」，很多人會想到向量資料庫。但我的知識庫一開始只有幾則 QA，直接把全部筆記交給 AI 最準、也最簡單。等知識庫大到放不下，再換成檢索也不遲。

**從自己架主機改成 Cloudflare Workers。** 一開始寫的版本要找一台主機常駐跑，後來改成 Workers：不用顧主機，也不用在自己電腦上跑任何東西。代價是 Slack 要求 3 秒內回應，但 AI 回答通常更久，所以中間加了一個 Queue：Worker 收到訊息先回 Slack「收到」，再把問題丟進 Queue 背景處理。

## 設定流水帳

一天下來大概是這樣：

1. **建 repo、寫骨架**：知識庫資料夾、負責人設定、回答邏輯、測試。先放了幾則假的 QA 讓流程能跑。
2. **放進第一則真的 QA**：剛好客服問了一題「這是客人關掉程式嗎？」，就拿來當第一則。寫的時候發現答案要分兩段：「給客人的回覆」和「內部說明」，不然 AI 會把技術細節一起講給客人聽。用詞也改了，「關閉瀏覽器」改成「**誤關**瀏覽器」，聽起來比較不像在怪客人。
3. **刪掉假資料**：假的 QA 會被 AI 拿來回答，正式上線前一定要清掉。
4. **改成部署在 Cloudflare Workers**：程式改完後，開始在三個網站之間來回設定：
   - **Cloudflare**：建一個 API token 給 GitHub Actions 部署用。範本預設沒有 Queues 的權限，要自己加
   - **Slack**：用設定檔（manifest）建 App。bot 的顯示名稱不能用中文，第一次貼上就報錯
   - **GitHub**：把 6 個 key 放進 Secrets
5. **第一次部署**：建 Slack App 時網址驗證失敗，因為那時 Worker 還沒部署。部署完再回 Slack 按 Retry 才通過。
6. **在 Slack 發問，bot 沒反應**：Logs 顯示 Slack 有把訊息送過來，但 bot 什麼都沒做，也沒留下原因。只好先加一行診斷紀錄，記下每則訊息「為什麼不回答」。結果找到兩個問題：
   - 在指定頻道 @bot 時，我把這種事件略過了，以為另一種事件會處理
   - 附截圖的訊息被 Slack 標成特殊類型，被當成「編輯訊息」一起略過
7. **終於回答了，但很難讀**：AI 回了一大段，還列出「如果是其他情況…」，長到被 Slack 折疊。Slack 的粗體符號遇到中文也不生效，直接把星號顯示出來。後來改成讓 AI 分欄位填內容（結論、回覆客人、內部說明），排版交給程式。
8. **讓 bot 看得懂截圖**：客服很常直接貼截圖。圖片沒辦法自動遮個資，所以規定客服貼圖前先去識別化，再讓 AI 讀圖。

回頭看，最有用的一件事是第 6 步的診斷紀錄。**讓系統說出「為什麼不做」，跟記錄「做了什麼」一樣重要。**

## 下一步

- 統計每天問幾題、AI 自己答掉幾題
- 讓行銷的需求也走同一套知識庫
